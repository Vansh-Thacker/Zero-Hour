1. The scenario 1-foundation/data/challenge.json

Everything about the attack and the controls is data in this one file. Your game should read it, not copy it into code.

2. The scoring module 1-foundation/starter/controls.mjs

Players choose all their controls once, before the attack starts. You give the module the scenario and the chosen control IDs. It checks the rules and gives back the money spent and the points for each phase. Try an example, or type control IDs yourself.

PhaseTimePoints from each chosen controlPhase points

The code that produced this

    
The module keeps no state and has no screens. Confirming the choice, revealing each phase, the checkpoint questions and the final outcome are your game.

  


  

    
3. The questions 1-foundation/data/questions.json

    
40 behaviour questions. Each has a topic, a difficulty tier, one correct answer and an explanation. 16 match a phase of the attack story.

    

      
      
    

    

    
Nothing here scores an answer. Your game asks them at a checkpoint after each phase. How many points a secure answer earns, and how the checkpoint looks, is yours to design.

  


  

    
4. A theme file 2-extend/themes/…/reference.json

    
A theme is a different way of showing the same game. This reads the result from section 2 and describes it in the words of each theme. The scoring does not change.
